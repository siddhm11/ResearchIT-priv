# ── Phase 3: Hybrid semantic search ──────────────────────────────────────────
# Pinned exactly, and deliberately.
#
# The previous ranges (FlagEmbedding>=1.2.9, transformers>=4.44,<5.0) resolve
# on a fresh build to FlagEmbedding 1.3.x plus a recent transformers, and
# BGE-M3 encoding then dies inside tokenizer.pad() with
#     AttributeError: 'list' object has no attribute 'keys'
# Confirmed on a clean environment 2026-07-30; 1.2.10 + 4.44.2 loads and
# encodes correctly on the same machine.
#
# This failure mode is silent in production: app/main.py catches the load
# error, logs "BGE-M3 not loaded", and search quietly degrades to the arXiv
# keyword API. The running Space is fine only because its image was built
# before those releases -- any rebuild would have picked them up.
FlagEmbedding==1.2.10
transformers==4.44.2

# sentence-transformers was never declared here -- it arrived transitively via
# FlagEmbedding, so a rebuild floated it to whatever was newest. That is the
# same drift the two pins above exist to stop, and it lands somewhere worse:
# the Dockerfile instantiates a CrossEncoder at BUILD time
#
#     RUN python -c "from sentence_transformers import CrossEncoder; ..."
#
# and app/reranker_bge_svc.py's graceful ImportError fallback cannot help a
# build step. A runtime failure degrades search to the RRF ordering; a failure
# here means the image never ships at all.
#
# 5.7.0 is what the resolver currently picks. Verified 2026-08-12 against the
# rest of this file on Python 3.12: CrossEncoder imports, instantiates
# 'cross-encoder/ms-marco-MiniLM-L-6-v2' and predicts. Pinned so the next
# rebuild cannot drift to a version nobody has run.
sentence-transformers==5.7.0
